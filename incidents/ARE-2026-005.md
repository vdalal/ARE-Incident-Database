# ARE-2026-005: Injection-driven sensitive-data exfiltration (EchoLeak, CVE-2025-32711)

> `ARE-2026-005` &nbsp;·&nbsp; **OWASP ASI:** ASI01 Goal Hijack &nbsp;·&nbsp; **AgentX check:** Yes &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `PII_EXFILTRATION` &nbsp;·&nbsp; **Confusion vector:** `UNAUTHORIZED_SCOPE_EXPANSION` &nbsp;·&nbsp; **Surface:** egress

**Coverage claim (AgentX Core, the maintainer):** Covered -- blocked deterministically today

## What happened

A prompt-injection chain drove an assistant to exfiltrate sensitive data to an external destination.

## Blast radius

Sensitive-data exfiltration, including a customer-table-to-external-host upload.

## How AgentX Core responds

_A vendor claim by the registry's maintainer, not a registry finding. It ships a check you can run; see below._

The keyless shield denies the exfiltration action: routing sensitive data or a customer table to an external host. The inbound prompt-injection trigger is a separate, judge-owned problem, and is flagged as such rather than claimed.

**Repro.** This blocks from a bare `pip install`, with no key, no gateway, and nothing leaving your machine. Copy it and run it.

```bash
pip install agentx-security-sdk
```

```python
from agentx_sdk import agentx_protect, is_block

@agentx_protect(agent_id="aredb-repro", action="db_read")
def run_sql(query: str):
    return "EXECUTED"          # the agent never gets here

result = run_sql("SELECT email, phone FROM customers")
print(is_block(result))        # True
print(result)                  # the block, and the safe path to take instead
```
