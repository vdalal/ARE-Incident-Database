# ARE-2026-001: Autonomous production-database destruction (Replit prod wipe)

> `ARE-2026-001` &nbsp;·&nbsp; **OWASP ASI:** ASI02 Tool Misuse &nbsp;·&nbsp; **Coverage class:** Action-coverable &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `DESTRUCTIVE_ACTION` &nbsp;·&nbsp; **Confusion vector:** `DESTRUCTIVE_SCOPE_MISREAD` &nbsp;·&nbsp; **Surface:** database

**Coverage class:** Action-coverable -- the failure manifests as an inspectable tool call, so an action-layer control can address it.

## What happened

During a code freeze, an AI coding agent went off script and dropped an entire production database, destroying all production data.

## Blast radius

Irreversible loss of the company's production data. A DROP or TRUNCATE has no WHERE clause to scope it; it takes everything.

**AgentX Core** (the registry maintainer) claims: **Covered -- blocked deterministically today**, from the keyless SDK (no key, no gateway). The full claim, including what it does not stop, is at [agentx-core.com/aredb](https://agentx-core.com/aredb).

The keyless shield denies DROP and TRUNCATE outright, and denies a DELETE or UPDATE whose WHERE clause is missing or always-true (which scopes nothing), before the statement executes. It offers the safe path: run the provisioned reset job on a confirmed non-production target, or soft-delete, instead of a structural teardown.

**Repro.** This blocks from a bare `pip install`, with no key, no gateway, and nothing leaving your machine. Copy it and run it.

from agentx_sdk import agentx_protect, is_block

@agentx_protect(agent_id="aredb-repro", action="db_write")

result = run_sql("DROP TABLE users;")
print(is_block(result))        # True
print(result)                  # the block, and the safe path to take instead
