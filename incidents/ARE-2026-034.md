# ARE-2026-034: Credential-stealing worm persisted through the agent's own config file (PyPI lightning, Mini Shai-Hulud, ChainDrop)

> `ARE-2026-034` &nbsp;·&nbsp; **OWASP ASI:** ASI04 Supply Chain &nbsp;·&nbsp; **Control domain:** Supply chain integrity &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `SUPPLY_CHAIN` &nbsp;·&nbsp; **Confusion vector:** `UNAUTHORIZED_SCOPE_EXPANSION` &nbsp;·&nbsp; **Surface:** package

## What happened

A family of at least four supply-chain campaigns between April and August 2026 used the same persistence step: a poisoned package writes an auto-run hook into the AI coding agent's own configuration, so the payload executes when a developer opens the repository or starts an agent session rather than at install time. It began on 30 April 2026, when PyPI versions 2.6.2 and 2.6.3 of `lightning` (PyTorch Lightning) shipped a hidden `_runtime` directory; Semgrep records that the malware "writes a SessionStart hook with matcher `*` into the repository's Claude Code settings, pointing to `node .vscode/setup.mjs`". It harvested GitHub and npm tokens, AWS credentials from the environment, `~/.aws/credentials` and IMDSv2, Azure Key Vault secrets, GCP Secret Manager values and GitHub Actions secrets. A cross-ecosystem worm called Mini Shai-Hulud, attributed to a group calling itself TeamPCP, followed in May across more than 170 npm and PyPI packages; a June variant named Miasma took down 73 Microsoft GitHub repositories; and on 4 August Microsoft published an analysis of ChainDrop, a Mini Shai-Hulud variant affecting "more than 400 packages across multiple unrelated publishers". Microsoft names the targeted paths directly, and Semgrep independently names the same two Claude paths in the April compromise: `.claude/settings.json`, `.claude/setup.mjs`, `.vscode/tasks.json`, `.vscode/setup.mjs`. The agent is the delivery vehicle here, not the actor: it takes no decision and issues no tool call.

## Blast radius

Credential theft across ecosystems and cloud providers, followed by self-propagation using the stolen publishing tokens. Whole package namespaces were republished by the attacker. Because the payload runs on repository open or session start, a developer who never installs the package is still exposed by cloning it.

## Who owns it

Supply-chain provenance and environment isolation. The controls that failed are package provenance and integrity verification, treating an agent's configuration files as reviewable code rather than inert settings, and not granting a repository's own configuration the power to execute on open. The payload runs at session start, before the agent has issued any tool call, so the failure sits upstream of anything that inspects what an agent does.
