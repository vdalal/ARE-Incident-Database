# ARE-2026-024: Destructive operation against the wrong environment (ERP reflection brittleness)

> `ARE-2026-024` &nbsp;·&nbsp; **OWASP ASI:** ASI02 Tool Misuse &nbsp;·&nbsp; **Control domain:** Action mediation &nbsp;·&nbsp; **Severity:** 2

**Failure mode:** `DESTRUCTIVE_ACTION` &nbsp;·&nbsp; **Confusion vector:** `ENVIRONMENT_CONFUSION` &nbsp;·&nbsp; **Surface:** filesystem

## What happened

An agent ran a destructive operation against the wrong directory or environment.

## Blast radius

Destruction in an unintended environment.

## Source

<https://news.ycombinator.com/item?id=46979781>

**AgentX Core** (the registry maintainer) claims: **Partial -- honest scope stated below**, from the keyless SDK (no key, no gateway). The full claim, including what it does not stop, is at [agentx-core.com/aredb](https://agentx-core.com/aredb).

Partial. The keyless shield covers the traversal and sensitive-target portion. The core "right command, wrong environment" judgment needs the org's ground truth and is left to the judge, not faked, since the shield cannot know which environment is correct.

**Check: CI-verified.** This registry executes this snippet on every push. It blocks from a bare `pip install`, with no key, no gateway, and nothing leaving your machine. Copy it and run it.

```bash
pip install agentx-security-sdk
```

```python
from agentx_sdk import agentx_protect, is_block

@agentx_protect(agent_id="aredb-repro", action="db_write")
def run_sql(query: str):
    return "EXECUTED"          # the agent never gets here

result = run_sql("TRUNCATE TABLE orders")
print(is_block(result))        # True
print(result)                  # the block, and the safe path to take instead
```
