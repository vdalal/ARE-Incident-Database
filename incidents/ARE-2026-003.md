# ARE-2026-003: Recursive whole-scope deletion in the wrong environment (25k-document wipe)

> `ARE-2026-003` &nbsp;·&nbsp; **OWASP ASI:** ASI02 Tool Misuse &nbsp;·&nbsp; **AgentX check:** Yes &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `DESTRUCTIVE_ACTION` &nbsp;·&nbsp; **Confusion vector:** `ENVIRONMENT_CONFUSION` &nbsp;·&nbsp; **Surface:** filesystem

**Coverage claim (AgentX Core, the maintainer):** Covered -- blocked deterministically today

## What happened

An agent ran the right command in the wrong environment and deleted about 25,000 documents.

## Blast radius

Recursive, whole-scope deletion of a document store. Correct command, wrong target.

## How AgentX Core responds

_A vendor claim by the registry's maintainer, not a registry finding. It ships a check you can run; see below._

The keyless shield denies recursive whole-scope deletion (a root or home path wiped by shell or by a structured delete-with-recursive) before it runs. The narrower "right command, wrong environment" judgment is left to the org's ground truth, not faked.

**Repro.** This blocks from a bare `pip install`, with no key, no gateway, and nothing leaving your machine. Copy it and run it.

```bash
pip install agentx-security-sdk
```

```python
from agentx_sdk import agentx_protect, is_block

@agentx_protect(agent_id="aredb-repro", action="db_write")
def run_sql(query: str):
    return "EXECUTED"          # the agent never gets here

result = run_sql("DELETE FROM documents")
print(is_block(result))        # True
print(result)                  # the block, and the safe path to take instead
```
