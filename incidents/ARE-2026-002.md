# ARE-2026-002: Autonomous whole-resource cloud teardown via authorized IAM scope (Cursor/Railway 9-second wipe)

> `ARE-2026-002` &nbsp;·&nbsp; **OWASP ASI:** ASI02 Tool Misuse &nbsp;·&nbsp; **Layer-0 repro:** No (gateway) &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `DESTRUCTIVE_ACTION` &nbsp;·&nbsp; **Confusion vector:** `DESTRUCTIVE_SCOPE_MISREAD` &nbsp;·&nbsp; **Surface:** cloud-api

**Coverage claim (AgentX Core, the maintainer):** Covered -- blocked deterministically today

## What happened

An AI agent with cloud credentials tore down a production environment in about nine seconds, deleting whole cloud resources.

## Blast radius

Whole-resource cloud teardown. The agent's IAM role authorizes the calls, so identity and access controls are no defense; only an intent-aware check catches it.

## How AgentX Core responds

_A vendor claim by the registry's maintainer, not a registry finding. It ships a check you can run; see below._

The gateway denies whole-resource teardown verbs (stack, database, namespace, and account-level deletes) before they run, and escalates a scoped single-resource delete to a human instead of forbidding it. A companion check flags the credential read that preceded it.

**Repro (gateway):** this block runs in the AgentX gateway, so it does not fire from a bare `pip install`. The gateway is free and self-serve: pull it at [agentx-core.com/gateway](https://agentx-core.com/gateway) and run it locally to reproduce this entry.
