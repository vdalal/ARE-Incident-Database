# ARE-2026-020: Server-side request forgery to cloud-metadata credentials (Casco agent compromise)

> `ARE-2026-020` &nbsp;·&nbsp; **OWASP ASI:** ASI02 Tool Misuse &nbsp;·&nbsp; **Control domain:** Action mediation &nbsp;·&nbsp; **Severity:** 1

**Failure mode:** `NETWORK_TRAVERSAL` &nbsp;·&nbsp; **Confusion vector:** `UNAUTHORIZED_SCOPE_EXPANSION` &nbsp;·&nbsp; **Surface:** fetch-url

## What happened

A red-team broke a majority of tested agents quickly; one vector drove an agent to fetch internal credentials via SSRF.

## Blast radius

Server-side request forgery to internal or cloud-metadata credentials.

**AgentX Core** (the registry maintainer) claims: **Covered -- blocked deterministically today**, from the keyless SDK (no key, no gateway). The full claim, including what it does not stop, is at [agentx-core.com/aredb](https://agentx-core.com/aredb).

The keyless shield denies the SSRF fetch (loopback, metadata IP, or a redirect that normalizes to one). This is one of three vectors in the incident; object-level authorization and sandbox escape are owned elsewhere and flagged, not claimed.

**Repro.** This blocks from a bare `pip install`, with no key, no gateway, and nothing leaving your machine. Copy it and run it.

```bash
pip install agentx-security-sdk
```

```python
from agentx_sdk import agentx_protect, is_block

@agentx_protect(agent_id="aredb-repro", action="network")
def http_get(url: str):
    return "EXECUTED"          # the agent never gets here

result = http_get("http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/")
print(is_block(result))        # True
print(result)                  # the block, and the safe path to take instead
```
